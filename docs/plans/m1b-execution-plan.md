# M1b 执行计划：只读数据闭环 → 资源绑定

> 日期：2026-09-18。状态：执行计划待启动；设计方向已获用户认可，功能尚未实施。
> 设计依据：`m1b-0-readonly-data-source-design.md`、ADR-0005、Proposed ADR-0009。
> 前置：阶段 0 PR #63 已合并为 fc133ef；交付前已确认合并后 main CI 成功（run 35320072208）。
> 本计划不授权自动实施、合并、关闭 Issue、迁移用户资产或连接真实业务接口。

## 1. 目标与交付分界

M1b-1 交付一个可演示且可验证的查询页面：保存 → 点击查询 → 服务端可信只读 Operation → Session State 更新 → 展示结果。重载不带上次查询数据，编译导出后在显式宿主下有相同行为。

M1b-2 在此基础上交付资源状态、只读 Table 分页和 Form 查询条件。M1b-1 不等待完整 Table/Form 产品能力；M1b 总体不能在只完成 M1b-1 时宣称全部完成。

暂缓：写操作、destructive、生产账号、自动重试、自动轮询、离线缓存、数据库 Catalog、OpenAPI 导入、MCP/Policy 平台、多租户与 PropertyPanel Preset 化。#38 A3 独立推进，不混入本计划。

## 2. 已认可的方向与实施前待定细节

采用精确 `{operationId, revision}`、具名 `logic.dataSources`、`executeDataSource`、整结果写入已声明顶层 State、同来源 latest-started-wins、草稿禁止执行、legacy/operation-only 分阶段隔离。

这些方向不意味着示意 JSON 已是最终协议。第一个 PR 开始前，在设计记录中锁定字段必选性、长度/数量上限、精确 Value 类型、安全状态目标语法、能力修订和 schemaVersion 兼容策略；必须复用现有 State/Flow 真实类型，不直接复制设计示例充当合法 fixture。

首版使用隔离本地示例服务与显式测试身份适配器。生产认证来源尚未确定：生产网络端点默认关闭；任何真实业务启用须另外完成可信用户/页面/Operation 授权适配。不可用客户端自报身份或匿名接口代替。

## 3. 基线与协作方式

1. 核实 fc133ef 的 main CI 成功；失败先判断是否来自阶段 0，不在 M1b PR 内顺手修不相关问题。
2. 保留当前设计 worktree 的未提交文档，先以独立 docs PR 固化设计、计划和 ADR 状态。现有设计 worktree 基于阶段 0 合并前提交，不直接把该旧祖先分支作为面向 main 的实施 PR；从最新 main 建隔离分支，仅转移设计文件，避免重复带入阶段 0 提交。
3. 每个实施 PR 从前一阶段已合并的最新 main 建独立 worktree。未合并时可本地探索，但不并行改共享 Contract/Runtime，也不跨阶段开放能力。
4. 每个 PR 固定审查 HEAD；补提交后重新检查相关范围。先最窄检查，再 PR 全量门禁；合并须单独获得授权。

## 4. M1b-1：按顺序拆成 5 个实施 PR

| PR                            | 范围                                                | 核心交付                                                         | 退出条件                                                        |
| ----------------------------- | --------------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------- |
| A：协议与拒绝门禁             | schema-contract、能力检查脚本及必要入口适配         | 新声明/动作、引用分析、显式能力矩阵、统一验证错误                | 新能力默认 unsupported，所有真实入口拒绝；旧能力不退化          |
| B：可信执行内核               | backend 数据源模块、宿主契约、隔离测试服务          | 静态 Resolver、授权接口、唯一 Executor、输入输出校验、限额/取消  | 未授权等前置拒绝零上游请求；不开放匿名生产路由                  |
| C：Renderer/Compiler 一致执行 | renderer session/action/host、compiler 两条动作路径 | 参数快照、结果提交、代际、取消、超时、Flow onError、显式宿主调用 | 同一 fixture 经真实 Renderer 与生成产物得到相同结果/错误/副作用 |
| D：编辑器与持久化闭环         | Agent/Editor、页面服务必要接线、测试                | 安全公开目录、Patch、模式 gate、CAS、回读、导出                  | 真实工具返回 Patch 经前端重放全等，真实仓储保存后重启回读并编译 |
| E：受控启用与交付             | 可信配置、能力矩阵、验收 fixture、文档              | 六消费面支持声明、受控 operation-only 演示、旧 apiCall 迁移清单  | 全矩阵通过后才启用；生产授权未就绪则只允许隔离演示              |

### PR A：协议先落地，能力先关闭

- 先写合法/非法 Contract fixture；必须区分“结构合法”与“当前部署允许执行/保存”。结构单测可走验证核心，不能为了测试而放开生产 gate。
- 新增 dataSources 和 executeDataSource；拒绝未知字段、危险键、无效引用、非法 resultTo、无版本/浮动版本、URL/Headers/风险等越界字段。
- 能力矩阵改为显式登记，新增能力默认 unsupported。覆盖直接 JSON 保存、Agent Patch、Preview、Compiler 等真实入口，不能只在前端隐藏。
- 保持当前 schemaVersion 与能力策略的兼容边界明确；若需要变更已持久化协议，停在设计评审点，不能自行升级并批量迁移。
- PR 内不得发起网络请求，不实现资源状态系统。A–D 的生产 gate 保持关闭；集成测试只能使用明确的可信测试配置。

### PR B：执行前先证明拒绝

- 静态注册唯一只读示例 `demo.items.search` 的精确 revision；operation 的输入输出和 readonly 风险来自可信注册。
- 请求绑定受授权页面版本与 sourceId；服务端回读快照解析引用。页面标识不是凭据，用户/租户身份来自可信适配器。
- Resolver/Executor 不接受 Schema 提供目标地址。敏感安全范围不能由 params 覆盖。
- 限制请求截止时间、响应字节、JSON 深度及并发；超大响应应在流读取过程中终止，不能完整读取后才检测。默认不跟随重定向，避免绕过目标约束。
- 测试使用 loopback 受控服务，仅测试配置允许该目标；生产默认禁止这种例外。输入/权限/能力失败断言上游计数为 0；输出不合法是请求后拒绝，不错误宣称零调用。
- 新端点即使存在，也必须在缺身份适配器时确定性拒绝。实现权限端口不等于生产鉴权已交付。

### PR C：运行与编译必须一起交付

- 先定义宿主请求/结果/错误/AbortSignal 契约，然后实现 Renderer 与普通动作、Flow 两条 Compiler 路径。
- 同 sourceId 启动新请求取消旧代际；校验后且仍为当前代际才提交结果。页面卸载/切换后禁止旧请求写入新 Session。
- 取消不可由 onError 吞掉，超时可恢复；保留旧结果。无自动重试，不同来源共享目标按成功提交顺序处理。
- 缺 dataResources 或宿主函数时拒绝，生成产物不得 fallback 到裸 fetch、context.api 或 apiCall。
- 用真实生成模块挂载、点击、等待受控服务结果验证，不仅比较代码字符串；两个 Preset 均覆盖，不用 AntD message 作为数据能力依赖。
- gate 未开放期间，只允许可信测试宿主执行新动作，不能把测试支持状态发布到生产默认清单。

### PR D：从实际工具出口串到真实仓储

- Agent 只获得有权使用的操作公开描述；目录过滤不能替代 B 的逐请求授权。
- UI 提供最小查询动作配置，不做完整 API 管理器。草稿显示“先保存再查询”。
- 真实 preview/write 工具返回 Patch → 真实前端 applyPatchToSchema → 与服务端预览完整相等 → 生产文件 Repository CAS → 新实例回读 → Compiler 真实产物执行。
- 快照仅含声明，响应数据、请求代际、AbortController、凭据、运行错误都不得持久化。
- operation-only 对嵌套 apiCall 递归拒绝，包括 if/loop/Flow/onError；宿主注入 context.api 不能绕过。legacy 保持旧语义但拒绝新能力，两模式不得由 Schema 切换。
- 现有模板和 fixture 的 apiCall 分类记录；不读取或迁移未经授权的用户页面。

### PR E：只在证据齐全后启用

- 每个能力/消费面记录对应测试与 HEAD，不依赖“全绿”一句话代替具体证据。
- 启用提交只处理可信 capability 配置与交付材料，避免夹带未审查功能。
- 受控演示可用测试身份和本地服务；若生产身份适配器未落实，明确“演示验收完成、生产外部执行未开放”，不阻塞无关离线工作，也不谎称生产可用。
- 默认部署模式切换、历史页面迁移和旧 apiCall 退役另行确认，不自动进行。

## 5. M1b-1 验收矩阵

| 场景                                                         | 必须观察到的证据                                          |
| ------------------------------------------------------------ | --------------------------------------------------------- |
| 正常查询                                                     | 真实上游返回，Session 更新，Renderer/导出产物一致         |
| 未知 operation/revision、未授权、伪造参数身份、缺 capability | 明确拒绝，上游请求计数 0                                  |
| 非法/超大结果                                                | 有请求但无 State 提交，错误脱敏                           |
| A 慢 B 快、取消、超时、卸载/切页                             | 当前 Session 无迟到写入；取消与超时处理符合 Flow 语义     |
| 嵌套 apiCall、新旧能力混用                                   | operation-only 全入口拒绝；legacy 不静默升级              |
| 保存/重载                                                    | 声明全等、运行值不持久化、精确引用不自动变更              |
| Patch/CAS                                                    | 实际返回 Patch 前端重放全等；真实仓储旧版本 409           |
| 导出缺宿主                                                   | 确定性拒绝，不出现网络回退                                |
| A/B Preset                                                   | 同名组件身份不串用，新网络能力不硬编码组件库              |
| 回归                                                         | M1a 能力、deterministic、原 Compiler/Runtime 断言全部保留 |

## 6. M1b-2：资源绑定，另分两个 PR

只有 M1b-1 完成才启动，不在 C 中顺手铺设资源框架。

F：资源语义与桥。基于已有 DataResourceState 定义 idle/loading/ready/error、旧数据保留、失败及取消后的状态；复用 B/C 的执行与代际，不另建网络层。补订阅/退订与 Session 销毁，Renderer 和生成产物一致。与直接 resultTo 的关系先冻结：资源是结果的只读消费面，不额外持久化第二份运行状态。

G：只读 Table/Form 场景。Form 只提供查询参数，Table 消费资源并支持分页、loading/error、显式重试；翻页时旧响应不得覆盖新页。无写表单、自动缓存或轮询。若 test Preset 无 Table，不为验收强塞组件；用其已有组件证明同一核心资源语义，AntD 负责 Table 产品验收。

M1b 总体验收：查询、分页、失败重试、取消、页面切换、保存重载、导出、权限拒绝齐全，六消费面门禁通过，已支持资产的旧 apiCall 处置明确。满足后再讨论 V1 冻结，不提前宣称冻结。

## 7. 每次交付必须包含

- base/head、独立 worktree、改动路径及与本阶段范围的对应关系。
- 运行的检查命令和结果；未跑项与原因；CI 必须对应最终 HEAD。
- 至少一个真实成功链和相关拒绝链，不用手写期望 Patch 代替实际输出。
- 尚未支持的能力、生产开关状态、回滚限制。新字段已被保存后，旧构建可能拒绝页面，不能保证直接回滚可用；必须备份快照、先关闭执行入口并明确兼容处理，不能删字段。
- 独立 PR，Refs 关联事项；不自动 Closes，不自动合并。

## 8. 停止条件与下一条可执行任务

遇到需新增生产认证体系、业务权限无法确定、现有 Flow 取消语义必须破坏性修改、需变更 Preset 公共 API 或持久化版本、必须迁移用户页面时，先给影响面和替代方案，停在决策点。普通未复现风险记录即可，不无限扩大阶段。

下一条实施任务仅为：main CI 成功且获得实施授权后，固化设计文档，再从最新 main 启动 PR A 的 Contract 与能力门禁。不要把本计划当成一次性完成 A–G 或自动启用生产的授权。
